# House Price Prediction

**Methods practised:** data cleaning and preprocessing pipelines (B1 Module 05), feature handling (Module 06),
regression models and metrics (Module 07), model saving and a simple API (Module 13).

## Problem statement

A property website wants to show buyers a fair price estimate for a house. Given a house's locality, size, age,
distance to the metro and amenities, predict its selling price in **lakh rupees**.

**Expected result:** a model that beats a "predict the average price" baseline by a wide margin, with its typical
error reported honestly, served through an API and a simple web form that shows the estimate and a likely range.
(The build run's actual numbers are in `VERIFICATION.md` and the executed notebook.)

## Dataset

Synthetic data for a fictional Indian city, generated by `data/generate_data.py`. Prices follow realistic rules
(price per sq ft depends on locality; older, farther-from-metro homes are cheaper; parking and furnishing add value)
plus random noise. See [data/DATA_DICTIONARY.md](data/DATA_DICTIONARY.md). The target column is `price_lakhs`.

## How to run (three terminals)

**1. Python environment and notebook** (from this project folder):

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate    macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
jupyter notebook notebook/House_Price_Prediction.ipynb     # Run All: this creates models/
```

The trained model is already included in `models/`, so you can skip straight to step 2 if you only want the app.

**2. Backend API** (same environment, from this project folder):

```bash
python backend/app.py                 # http://localhost:5000
python -m unittest discover -s backend -p "test_*.py" -v    # optional: run the tests
```

Try it without the frontend:

```bash
curl http://localhost:5000/api/health
curl -X POST http://localhost:5000/api/predict -H "Content-Type: application/json" \
  -d '{"area_sqft":1200,"bedrooms":2,"bathrooms":2,"age_years":5,"distance_to_metro_km":1.5,"floor":4,"locality":"Tech City","parking":"Yes","furnishing":"Semi-Furnished"}'
```

**3. Frontend** (needs Node.js 18+):

```bash
cd frontend
npm install
npm run dev                           # open http://localhost:5173
```

If the API runs somewhere else, copy `.env.example` to `.env` and change `VITE_API_URL`. If the frontend runs on a
different address, start the backend with `FRONTEND_ORIGIN=http://that-address python backend/app.py`.

## Architecture and request flow

```
 Browser (React form)                 Flask API (backend/app.py)                 models/
 ───────────────────                  ──────────────────────────                 ───────
 page opens ── GET /api/options ───▶  read model_info.json (loaded at start) ◀── model_info.json
            ◀── localities, ranges ──
 user submits ─ POST /api/predict ─▶  1. parse JSON (400 if not JSON)
   {area_sqft: 1200, ...}             2. validate every field (422 + per-field messages)
                                      3. one-row DataFrame → pipeline.predict ◀── house_price_model.joblib
            ◀── 200 {predicted_price_lakhs, likely_range_lakhs, model, note}
 shows price and range, or the error next to the right field
```

- The model is **trained once in the notebook** and loaded **once when the API starts**. Requests only call `predict`.
- The saved object is the **whole pipeline**, so missing-value filling, scaling and one-hot encoding are applied exactly
  as during training.
- The likely range is *prediction ± test MAE* — a simple, honest way to show uncertainty to a non-technical user.

### API reference

| Method | Path | Request | Success response | Errors |
|---|---|---|---|---|
| GET | `/api/health` | — | `{"status": "ok", "model": "..."}` | — |
| GET | `/api/options` | — | `{"categories": {...}, "numeric_ranges": {...}, "model": "...", "test_mae_lakhs": n}` | — |
| POST | `/api/predict` | JSON with the 9 house fields | `{"predicted_price_lakhs": n, "likely_range_lakhs": [lo, hi], "model": "...", "note": "..."}` | 400 body not JSON; 422 `{"error", "fields": {field: message}}` |

Validation rules: all fields required; numbers must lie inside the training ranges (the model cannot extrapolate);
bedrooms, bathrooms and floor must be whole numbers; categorical values must be ones the model has seen;
bathrooms more than bedrooms + 2 is rejected as a likely typo.
